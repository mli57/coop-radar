# coop-radar

Watches a list of companies' career pages and pings Discord the moment a new
intern/co-op posting shows up. This is a work in progress, I'm still adding new functionalities.

## Why this exists

Through my experience applying to co-op positions this past year, I've found that a really big issue is applying too late. By the time I see a posting, it's already been live for days, and the applicant pool has grown large.

I've tried a few approaches to finding postings earlier. Job aggregators on GitHub and conventional job finding platforms (LinkedIn, Indeed, etc.) routienly lag behind, since their listings tend to show up days after the role went live on the company's own site. Checking career pages by hand catches postings on day one, but it doesn't scale past a handful of companies, and is quite inefficient as I can't always be camping the corporate website.

coop-radar does that checking for applicants(you and me). it scrapes each company's careers page on a schedule, compares the result against what it saw last time, and
only bothers you about what's actually new.

## How it works

- **Recipes** (`config/recipes.json`) describe how to pull postings from one company. Most companies rent their job board from a platform (Ashby, Greenhouse, Lever, Workday, Recruitee) that exposes the listings as a queryable API, and no browser needed. Companies that built their own board fall back to a `css` recipe generated with the help of an LLM, which drives a headless browser against the rendered page instead.
- **Bootstrapping** (`src/agent.ts`) figures out a new company's recipe automatically, and re-runs itself if a previously-working recipe stops returning results (the board likely changed shape).
- **Diffing** (`src/differ.ts`) saves a snapshot of each company's postings after every run and compares against it next time, so only postings that are actually new get reported.
- **Notifying** (`src/notifier.ts`) sends a summary of every new posting to Discord, plus an immediate `@here` alert for postings at companies/titles marked high priority in `config/priorities.yaml`.

## Install

```
npm install
npx playwright install chromium   # needed for css-recipe companies, which drive a real browser
```

## Setup
You would need to create your own discord server first. Then you will need to create two separate webhooks(one for normal postings, the other for the important postings from companies you care about).

In Discord: Server Settings, Integrations, Webhooks, New Webhook, once per channel. Copy each webhook's URL.

Then create a `.env` file in the project root with:

```
BRIEF_WEBHOOK_URL=https://discord.com/api/webhooks/...
ALERT_WEBHOOK_URL=https://discord.com/api/webhooks/...
```

`BRIEF_WEBHOOK_URL` is where the regular per-run summary goes. `ALERT_WEBHOOK_URL` is where the `@here` priority pings go. The `.env` file is loaded automatically on startup if it exists.

You would also need to setup a cron job since the github one doesnt run on time.

## Usage

```
npm run bootstrap -- [company]   # generate a recipe for one company (or all companies missing one)
npm run monitor                   # scrape everything, diff, and notify
```

## Config

- `config/companies.yaml`: companies to track and their careers page URL.
- `config/recipes.json`: how to scrape each company (generated by `--bootstrap`, hand-editable).
- `config/priorities.yaml`: companies/keywords that trigger an immediate alert instead of waiting for the regular summary.
